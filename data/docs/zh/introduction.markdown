TeaNode 让每个副业项目、每家早期创业公司都有一个自己域名下的真实邮件地址，而不用为每一个再维护一个邮箱。

它是一个小巧的自托管邮件服务器。它通过 SMTP 为你所有的域名接收邮件，验证邮件是否真实（SPF、DKIM、DMARC、ARC），可选地扫描病毒和垃圾邮件，然后转发到你指定的任何地方——你真正的邮箱、一个 webhook，或另一台邮件服务器。它也为你自己的设备中继外发邮件，并用你域名的密钥签名，让邮件真正送达，而不是落进垃圾箱。

它刻意**不做**邮箱服务器。没有 IMAP，也没有收件箱。你现在在哪里读邮件，就继续在哪里读；TeaNode 负责的是域名、身份验证和路由。

## 为什么

为一个域名运行邮件服务，通常要么交给服务商，要么把 Postfix、Dovecot、OpenDKIM、OpenDMARC、SpamAssassin 和一个策略守护进程拼装起来，并让它们保持一致。这里只有一个可执行文件和一个 PostgreSQL 数据库，而决定你的邮件是否可信的身份验证是内建的，不是后加上去的。

## 它长什么样

仪表盘编译在二进制文件里；没有别的东西需要部署。

## 你需要什么

- 一个域名，以及编辑它的 DNS 的能力
- 一台地址稳定的主机，25、80、443 和 587 端口可以访问
- PostgreSQL，用来保存配置和处理过的邮件

别的什么都不需要。不需要 AWS 账号，不需要 Redis。证书通过 HTTP-01 自动获取，所以没有 DNS API 需要配置。兼容 S3 的对象存储是可选的，只有在运行多个实例时才值得配置：它让各个实例共享存储的邮件。

## 它能做什么

**验证每一封邮件。** 进来的邮件经过 SPF、DKIM、DMARC 和 ARC 检查，结果按邮件逐一显示。你的外发邮件带 DKIM 签名，转发的邮件保留 ARC 链，到了对方那里依然能通过验证。

**灵活转发。** 别名用正则表达式匹配地址，把邮件送到一个邮箱地址、一个 HTTP 端点，或另一台邮件服务器。空的模式是兜底别名，接收其他别名都没有匹配到的邮件。

**中继你的外发邮件。** 在提交端口上为每台设备配一份 SMTP 凭据，每份凭据都可以限制为只用一个发件地址。

**让你看到邮件。** 仪表盘把一封邮件当作邮件来呈现：身份验证的判定、每次投递尝试以及失败的原因，还有去掉脚本的正文本身，远程图片在你要求之前不会加载。

**发送你写的邮件。** 带变量和翻译的模板、包在外面的版式、从你自己的域名提供的图片，以及收件人的邮件程序是否加载了它们的记录。

**报告你的域名状况。** 收到的 DMARC 汇总报告会被解析并保存，这就是你发现有人伪造你的域名的方式。

**可选的附加功能，默认全部关闭。** ClamAV、SpamAssassin、GeoIP、存储邮件的 S3 镜像、供地址信誉不佳的主机使用的外发 SOCKS5 代理，以及需要通配符证书时的 DNS-01。

## 一封邮件如何经过它

1. SMTP 监听器处理协议，可选地完成 STARTTLS 和身份认证，并生成一个信封。
2. 信封决定走四条路径中的哪一条：带签名的退信地址或报告地址意味着一封投递状态通知或一份 DMARC 汇总报告；一份凭据意味着外发提交；其余都是入站邮件。
3. 入站邮件接受检查——SPF、DKIM、DMARC 和 ARC 并行进行，然后是可选的病毒和垃圾邮件扫描——并连同每项检查的结论一起记录下来。收件地址的本地部分与该域名的别名逐一匹配，每匹配一个就产生一次投递：一个邮箱、一个 webhook，或另一台邮件服务器。
4. 外发邮件用域名的密钥签名后中继出去。失败的投递会按固定的退避阶梯重试，队列页面会用对方服务器自己的话说明失败的原因。

每一步都是仪表盘能让你看到发生了什么的地方，这正是记录它们的意义。

## 配置

配置存放在数据库里，所以多个实例共享同一个答案，在仪表盘里做的修改会到达所有实例。环境变量只说明数据库在哪里；其余一切都存储在数据库中。

```yaml
domains:
  - id: example.com
    domain: example.com
    subdomain: mail
    aliases:
      - id: 01K2ZQ7B8N6H4K2QDX8ZR5VTAE
        pattern: ^hello$
        kind: email
        email: you@example.net
      - id: 01K2ZQ7B8PA1M7CJW3YFB9SDQK
        pattern: ""            # 兜底别名
        kind: email
        email: everything@example.net
```

这就是 `teanode-server config show` 打印的内容，也是 `teanode-server config import` 读取的内容，所以整台服务器可以写在一个文件里、纳入版本控制并加载——但运行中的服务器以数据库为准。[配置](/doc/configuration)记录了每一个字段。
