TeaNode 让每个副业项目、每家早期创业公司都有一个自己域名下的真实邮件地址。

它是一个小巧的自托管邮件服务器。它通过 SMTP 接收你所有域名的邮件，验证邮件是否真实
（SPF、DKIM、DMARC、ARC），可选地扫描病毒和垃圾邮件，然后要么把它归入这里的一个邮箱，
要么把它交出去——转发到你已经在读的邮箱、一个 webhook，或者另一台邮件服务器。你也可以用
这些地址回复和发信，邮件用域名的密钥签名，真正送达，而不是落进垃圾箱。

邮箱可以在仪表盘里读，也可以用任何邮件程序通过 IMAP 读。不需要邮箱的地址就直接转发，
同一个域名两种都能用。

## 为什么

为一个域名运行邮件服务，通常要么交给服务商，要么把 Postfix、Dovecot、OpenDKIM、
OpenDMARC、SpamAssassin 和一个策略守护进程拼装起来，并让它们保持一致。这里是一个
可执行文件加一个 PostgreSQL 数据库，决定你的邮件是否可信的身份验证是内建的，而不是外挂的。

## 它长什么样

仪表盘被编译进二进制文件里，没有别的东西需要部署。它打开时就是你的邮箱，运行服务器的那些
页面在 **管理** 后面，只显示你的权限允许的内容。

## 你需要什么

- 一个域名，以及编辑它的 DNS 的能力
- 一台地址稳定的主机，25、80、443 和 587 端口可以访问；如果要让邮件程序读取邮箱，
  还需要 993 端口
- PostgreSQL，用来存放配置、邮箱，以及它处理过的邮件

别的什么都不需要。不需要 AWS 账号。证书通过 HTTP-01 自动获取，所以没有 DNS API 需要配置。
S3 兼容的对象存储是可选的，只有在你运行多个实例时才值得有：它是让这些实例共享存储邮件的东西。

## 它能做什么

**邮箱。** 每个账户都有一个。文件夹可以嵌套到任意深度，可以改名、移动和置顶；搜索可以只在
一个文件夹里，也可以覆盖整个邮箱，并带发件人、收件人、主题、日期和附件筛选；规则在邮件到达
时归档，也可以对已经归档的邮件重新运行。还有附件只上传一次的草稿、签名、从你写信的对象那里
积累起来的联系人，以及一个知道不去回复机器、邮件列表或另一个也在外出的邮箱的外出自动回复。
一封邮件只存一份，无论有多少个文件夹放着它，只要还有一个放着就一直保留。

**IMAP。** 993 端口，以及 143 端口上的 STARTTLS，这样邮件程序读的是同一个邮箱。每台设备
有自己的应用专用密码，用它登录 IMAP，也用它在 587 提交端口上以邮箱的任何一个地址发信。

**验证每一封邮件。** 进来的邮件经过 SPF、DKIM、DMARC 和 ARC 检查，结果按邮件逐一显示。
你的外发邮件带 DKIM 签名，转发的邮件保留 ARC 链，到了对方那里依然能通过验证。

**灵活转发。** 别名用正则表达式匹配地址，投递进一个邮箱，或者把邮件送到一个邮箱地址、
一个 HTTP 端点，或另一台邮件服务器。空的模式是兜底别名，接收其他别名都没有匹配到的邮件。

**中继你的外发邮件。** 在提交端口上为每台设备配一份 SMTP 凭据，每份都可以限制为只用一个
发件地址。

**人员、群组和角色。** 权限决定每个人看到什么：Administrator、Operator 和 Member 是预置的，
而且全都可以编辑；一个群组可以绑定到一个域名，它的权限就只到那里为止。通过 OpenID Connect
提供商的单点登录会跟随你自己目录里的一个群组。对用户、群组、角色、域名、别名、凭据或邮箱的
每一次改动都在审计日志里。

**让你看到邮件。** 仪表盘把一封邮件当作邮件来呈现：身份验证的判定、投递尝试及其失败的原因，
以及去掉脚本的正文本身，远程图片在你要求之前不会加载。

**发送你写的邮件。** 带变量和翻译的模板、包在外面的版式、从你自己的域名提供的图片，以及
收件人的邮件程序是否加载了它们的记录。

**报告你的域名状况。** 收到的 DMARC 汇总报告会被解析并保存，这就是你发现有人伪造你的域名的方式。

**不用第二个程序就能给垃圾邮件打分。** 服务器内部的过滤器读取它已经确定的东西——SPF、DKIM、
DMARC 和 ARC 的结果、发送主机是否有前向确认的反向 DNS 名字、它在 HELO 里报的名字——
通过 DNS 查询公共黑名单，并应用一个用你在仪表盘里标记的邮件训练出来的分类器。对于想要的
部署，外部的 SpamAssassin 守护进程依然受支持。

**可选的附加功能，默认全部关闭。** ClamAV、GeoIP、存储邮件的 S3 镜像、供地址信誉不佳的主机
使用的外发 SOCKS5 代理，以及需要通配符证书时的 DNS-01。

## 一封邮件是怎么穿过它的

1. SMTP 监听器说这个协议，可选地做 STARTTLS 和认证，产出一个信封。
2. 信封走四条路径之一：签名过的退信或报告地址意味着一份投递状态通知或一份 DMARC 汇总报告；
   一份凭据意味着外发提交；其余的都是入站邮件。
3. 入站邮件会被检查——SPF、DKIM、DMARC 和 ARC 并行进行，然后是可选的病毒和垃圾邮件扫描
   ——并连同每一项检查的结论一起记录下来。收件人的本地部分会与该域名的别名匹配，每命中一个
   就创建一次投递：一个邮箱、别处的一个地址、一个 webhook，或另一台邮件服务器。
4. 投递到邮箱会归入一个指向已存邮件的引用，运行邮箱的规则，并更新未读计数。投递到别处的
   邮件用域名的密钥签名并中继出去；失败的会按固定的退避阶梯重试，队列页面用对方服务器自己的
   话说明失败原因。

每一步都是仪表盘可以告诉你发生了什么的地方，而这正是记录它们的意义。

## 配置

设置存放在数据库里，所以多个实例共享同一个答案，在仪表盘里做的改动也会到达所有实例。域名、
别名、凭据和账户是一行一行管理的记录。环境变量只说明数据库在哪里；其余一切都存储在里面。

    teanode domain create example.com
    teanode alias create example.com --pattern '^you$' --kind mailbox --mailbox <邮箱 id>
    teanode alias create example.com --pattern '^hello$' --kind email --email you@example.net

[命令行](/doc/command-line)覆盖整个 API，[配置](/doc/configuration)记录了每一项设置。
