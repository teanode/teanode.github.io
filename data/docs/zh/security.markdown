请不要为任何可被利用的问题开公开的 issue。这包括邮件处理——SPF、DKIM、DMARC 和 ARC 验证、邮件头解析、MIME 读取器——以及身份认证、会话处理、证书签发，还有仪表盘筛选功能背后的聚合流水线。

请通过 GitHub 的私密漏洞报告提交，入口在本仓库的 [Security 标签页](https://github.com/ziyan/teanode/security/advisories/new)。在公告发布之前，它只对维护者可见，也给了我们一个不是公开 issue 的讨论场所。

告诉我们你做了什么、发生了什么、你预期的是什么。一封能复现问题的邮件——一个 `.eml` 文件、一段 SMTP 会话记录、一个请求——比一段描述更有价值。

## 哪些在范围内

本仓库中的程序，在其默认配置下。具体来说：在 25 端口接收邮件、在 587 端口的认证提交、`/api/v1` 下的一切，以及它获取的证书。

## 哪些不在

- 任何需要运维者自身凭据或配置权限的问题。这是单租户软件；运维者是被信任的，文档中描述的让他们访问自己网络的方式——webhook 别名、转发目标、中继主机——都是功能。
- 它被配置去连接的服务：PostgreSQL、ClamAV、SpamAssassin、对象存储。它们按配置被信任，这正是文档要求把它们放在公网之外的原因。
- 靠流量堆出来的拒绝服务。算法复杂度导致的拒绝服务在范围内。

## 已经检查过的内容

[`docs/security/security-review.md`](/doc/security-review) 记录了对整个程序的一次审查：发现了什么、修复了什么、还有什么未解决，以及审查没有覆盖的部分。先读它，可以避免你再去发现一个已经写下来的问题。
