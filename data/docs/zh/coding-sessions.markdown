如果你同时开着好几个 Claude Code 和 Codex 会话，每个在自己的终端里，你的代理可以在你身边一起在
里面干活。它看得到你接上的每一台电脑上的每一个会话，读每一个做了什么，在你看得到的地方往其中一个
里输入一条指令，并把它们停下来问的问题带给你，所以你不在桌前的时候，可以从抽屉、从手机，或者从一个
会说 MCP 的聊天应用里回答。

它是通过 [herdr](https://herdr.dev) 做到的。herdr 是一个给编程助手用的终端工作区管理器，它把终端放在
一个个窗格里，并认得出每个窗格里是哪个编程助手。

## 你需要什么

- 你的电脑上跑着 herdr，你的编程会话开在它的窗格里。
- 那台电脑上用最新的 `teanode` 运行着 `teanode computer start`。电脑上的这个程序盯着 herdr 的
  socket，并向你的服务器报告；别的什么都不用装。

每个人的会话只属于自己：这个程序以你的身份登录，只有你的代理看得到你的窗格。

## 它会做什么

**列出它们。** 代理页面「连接」标签上的「herdr 会话」卡片、`teanode computer herdr list`，以及代理的
`herdr` 工具，都会显示每一个会话：它在 herdr 里的名字、它是工作中、空闲还是在提问、它是哪个编程助手、
所在的电脑、目录和标题。在提问的会话排在最前面。

**读它们。** 一个会话历史里的最后几轮，或者它的窗格此刻显示的内容。

**往里输入。** 一条指令会当着你的面输入到窗格里，和你自己打进去的一样；正在工作的会话会把它当成它
这一轮里的一条消息来读。只有一个进程、一份历史、一块屏幕，由你和代理共用，你随时都可以接手。

**把它们的问题带给你。** 一个会话停下来问东西的时候（选哪个选项、能不能运行一条命令或者改一处、
你批不批准它的计划），这个问题会写进你的主对话里。抽屉会打开，选项变成按钮，同一个问题也会发到你
接入的聊天应用。谁先回答算谁的：电脑上的程序在按下你的回答之前会再读一遍屏幕，如果问题已经没了
或者变了，就拒绝这个回答。

**做完了告诉你。** 让代理盯着一个会话，那个会话做完它这一轮时，你提出要求的那个对话就会被唤醒，所以
「测试通过了告诉我，然后让它去开 pull request」是行得通的。

**打开和关闭它们。** 在一个目录里开一个新的 Claude Code 或 Codex 会话，放在以这个目录命名的工作区的
一个新标签里；你要求的话，也可以关掉它的权限确认。一个会话只有在不工作时才会被关闭。

## 从任何地方

这些动作每一个都在代理的 `herdr` 工具上，所以凡是能够到你代理的，都能够到你的编程会话。抽屉里的一通
[语音通话](/doc/voice)可以问每个会话在做什么，并回答正在等着的那一个。ChatGPT、Grok，或者任何一个
会说 Model Context Protocol 的助手，一旦[接到你的服务器上](/doc/mcp)，也都可以：从手机上问它，愿意的话
在车里用说的，问你的会话们在忙什么，再告诉其中一个接下来做什么。

对一个 MCP 客户端，这个工具声明自己是只读的（这是凭你的一句话），所以这些助手每次运行它都不会先问；
大多数助手不会让你对一个会写东西的工具设成总是允许。输入和回答在仪表盘里也不会弹出确认卡片，因为每个
回答都要一张卡片，超出了人们想要的。如果你想要，就把 `herdr` 放进你自己的「先问我」清单。

## 会话里也知道你的代理知道的事

反过来那个方向用不着 herdr。`teanode hook install claude-code`（或者 `codex`）让那台电脑上的每一个
会话都看到你的代理对它所在的检出知道些什么：开始时是项目的页面和那里上一个会话停在了哪里，每条
提示只从这个项目里想起的东西，以及每个回答之后一分钟内就读进来的它自己的对话记录。
[编程会话里的记忆](/doc/coding-memory)讲了细节。

## 它怎么知道一个会话在提问

靠屏幕。这个程序认得出当前版本的 Claude Code 和 Codex 为一个问题、一次批准和一份计划画出来的表单，
并自己判断每个会话的状态，而不是采用 herdr 的判断，因为往一个表单里输入指令就等于回答了它。一个画法
不同的编程助手，在识别器学会它之前是认不出来的；那时这个会话会显示为空闲或者未知，它的屏幕照样能读。

`teanode computer herdr setup` 还可以把报告钩子加进那台电脑上 Claude Code 的设置里，和已有的钩子放在
一起，并先留一份那个文件的副本。它们只报告发生了什么，不做任何决定。只有你要求时才会加进去，因为它们
会改你的 Claude Code 设置。

电脑上的程序重启（每次升级都会重启）既不会丢掉一个还在等的问题，也不会丢掉一个「完成时告诉我」。
