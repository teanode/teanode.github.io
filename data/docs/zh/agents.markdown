TeaNode 服务器上的每个账户都可以有一个属于自己的代理：读到达的邮件、给它们分类、写
草稿，并回答关于它们的问题。这一页讲运维者要打开什么，以及一个人拿到它之后能做什么。

一个模型和任何人的邮件之间隔着两道开关，而且两道都必须用手打开。运维者配置一个模型
服务并打开这个功能，光这样谁也不会有代理；然后每个人打开自己的那一个，并且逐个邮箱地
授予它。在这两件事都发生之前，关于一封邮件的任何东西都不会被送到任何地方。

## 它需要什么

一个模型服务。TeaNode 会和 OpenAI、Anthropic、Gemini 说话，也会和任何回答 OpenAI API
的东西说话——其中包括同一台机器上的 [Ollama](https://ollama.com/)，而那正是什么都不会
离开你服务器的那种配置。

其他什么都不需要。代理和别的一切跑在同一个可执行文件里，它取活的队列也在同一个
PostgreSQL 里。

## 打开它

作为运维者，在服务器页面的 **代理** 标签页上：添加一个提供方——它的种类、它在哪里监听、
它的密钥——然后说清楚哪个模型做哪种活。`default` 是必须的，`fast` 是便宜的活用的，
`embedding` 是让按意义搜索成为可能的那个。测试按钮就在提供方那一行上。

    teanode settings set agent enabled=true
    teanode settings describe agent          # 每一个键，带类型

密钥在存下之前会用服务器密钥封起来，就像一个域名的签名密钥那样：数据库导出里是密文，
用另一个密钥启动的服务器读不出来，并且会这么告诉你。

然后，作为一个人，在 **设置 → 代理** 上：打开你的代理，并授予它一个邮箱。授予是按邮箱
来的，下面的每一件事也都是——你可能想在一个地址上分类，而在另一个地址上什么都不要。

## 它会做什么

**给到达的邮件分类。** 一个类别、一个优先级、是否有人在等回复、一行摘要，以及这封邮件
要求的东西。它们作为标签出现在行上，并且在「星标」旁边有一个「优先」视图。你的邮箱规则
可以读它的判断——「类别是订阅信，移到 Reading」——而这些规则是在分类做完之后跑的，不是
在投递的时候。

**做摘要和草稿。** 超过三封邮件的会话上方会折起一段摘要，并随着会话变长而重写。回复时，
撰写框会主动提出替你写一封：你说这封回信要做什么，文字就落进编辑器里，用你自己的口吻和
落款。发出去这件事仍然是你的。

**替你回复，如果你允许。** 一个邮箱可以让代理按你写的策略代你回信：它可以回复谁、哪几类
邮件、什么时候、一封回信要等多久、一天几封。每一封回信都停在草稿里，带一条横幅让你取消它
或者接手——而你去编辑它就是接手。在动笔之前和寄出之前，它都会走一遍外出自动回复走的那道
阶梯：绝不回给邮件列表、退信、自动邮件、垃圾邮件，或者并非寄给你的邮件。

**回答你的问题。** 仪表盘每一页上的一个抽屉，以及终端里的 `teanode agent ask`。它通过
仪表盘用的同一批操作来工作，以你的身份，用的正好是你的权限：它搜索你的邮件、读它、归档
它、起草，管理你的文件夹和规则。任何撤不回来的事情，以及任何要离开服务器的事情，都会停在
一张卡片上等你批准或者拒绝。

**记住东西。** 关于你的事实，跨会话地记着——会计是谁、你怎么落款、什么绝对不要自动回复。
它也从你的手上学：一封你把它归到别处而不是它分类到的地方的邮件，会成为下一次运行时给它
看的例子。

## 它要花多少，以及怎么封顶

每一次运行都会计数，运维者可以按 token 或者按钱封顶。`agent.limits` 里有
`dailyTokensPerAgent` 和 `monthlyTokensPerServer`，旁边还有 `dailyCostPerAgent` 和
`monthlyCostPerServer`；也可以给某一个人单独定：

    teanode agent admin limit alice --cost 5

按钱的预算是用每个提供方所配置的价格、按模型来计价的，所以一个同时跑小模型和大模型的
部署，两边都算得对。两种预算都设了的时候，先用完的那个结束这一天。`agent.currency` 说明
这些金额用哪个三字母代码来写；它只负责标注和格式，不做换算。

一个人在聊天窗口顶部看到自己这一天，是一个环；运维者在服务器页面的代理标签页上看到按天、
按种类、按邮箱、按模型的用量。

## 打开它之前值得想清楚的事

除非你自己跑一个，否则语言模型就是第三方。到达它那里的邮件就是离开了你服务器的邮件，而
自己跑邮件服务器的意义，通常恰恰是邮件不会离开。由此有三件事。

先授予它一个邮箱，看清楚它做了什么，再授予下一个。授予是关于一整个邮箱的决定，而打开
按意义搜索，会把已经在那里的邮件也和之后到达的一起送去做向量。

如果邮件是敏感的，就把它指向一个 Ollama。同样的功能都能用，分类的质量取决于你跑的是哪个
模型，而没有任何东西离开这台机器。

在向所有人开放之前，先读 `agent.features`。它说明人们到底可以打开哪些东西；一个想要分类
但不想要自动回复的运维者，应该在那里说出来，而不是指望每个人都不去碰那个开关。
