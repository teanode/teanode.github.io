一个在两次对话之间就把你忘光的代理，不过是一个讲礼貌的搜索框。这一页讲的是：你的代理
留下了什么、这些东西怎么在你不开口的情况下被写下来、它还会去哪里读，以及在没人跟它说话
的时候，它拿这些做了什么。

这些都要等你打开自己的代理、并且授予它一些东西之后才会发生。这里写的每一件事，背后都有
一个你亲手打开的开关。

## 它的形状

你的代理知道的东西，是一张由**页面**构成的图，而不是一串笔记。

一个**页面**就是你生活里有名字的某样东西：一个人、一个项目、一个组织、一个地方、一件
东西、一个话题、一段时间。它住在一条路径上——`people/alice-chen`、`projects/greenfinch`、
`time/2026/09`——而这条路径就是它到处通用的地址：在提示词里、在引用里、在命令行上，
以及在仪表盘自己的网址里。

一条**事实**是页面上的一句话，带编号。`people/alice-chen#3` 就是你的代理关于 Alice
知道的第三件事，它在回答里就是这样引用的，你也是这样再找回那一行的。编号不会被重用，
所以划掉 #3 不会把这个号让给下一条写进来的东西。每条事实都带着它所依据的原话，以及这
些话来自哪里——一次对话、一封邮件、一个文件——所以一行是可以核对的；仪表盘会告诉你哪些
行可以核对，哪些不行。

一条事实带着两个日期，因为它们回答的是不同的问题：它是什么时候成立的，和代理是什么时候
知道的。「他们搬去了大阪」这件事发生在 2019 年，而代理是上周二才知道的；一个关于 2019
年的问题要的是前者。

一条**连线**把两个页面连起来，并说明是怎么连的。不是「相关」，而是 `works_on`、
`member_of`、`knows`、`owns`、`uses`、`located_in`、`decided_in`、`about`、
`part_of`。每一种都能反过来读——从 Alice 到一个项目的连线，在她的页面上念作「在做」，
在项目的页面上念作「由谁在做」——而长期没人碰过的一条连线会用过去时来说，这是表明它可能
已经不成立的、最克制也最诚实的办法。

这些你都在 **设置 → 知识** 里读和改，而且那里的每一件事，命令行上也都有：

    teanode agent memory index                      # 图的顶部
    teanode agent memory get people/alice-chen
    teanode agent memory note projects/greenfinch "账期改成了九十天"
    teanode agent memory link people/alice-chen projects/greenfinch --relation works_on
    teanode agent memory move notes/kittiwake things
    teanode agent memory merge work/old-portal projects/greenfinch
    teanode agent memory history projects/greenfinch

一个页面还有**别的名字**。你在对话里怎么称呼一样东西，往往不是它的标题——「那个门户」
「Greenfinch」「理赔那个玩意儿」——而别名就是你的代理在你用了别的叫法时还能找到这个页面的
办法。它们在知识页面上就挨着页面的名字，命令行上是 `memory page --alias`。

## 不用你开口，它自己写

这件事的第一版，是请模型在一个回合当中自己去写记忆。在一台真实的服务器上，456 个回合里
它写了两条，而且都是测试。给一个模型一个任务和一个记忆工具，它会去做那个任务。

所以写不发生在回合里。一次对话安静下来之后，有一个任务会去读刚才说了什么，并把这次对话
教给它的东西记下来：找到或者新建的页面、连同原话一起加上的事实、画出来的连线。它知道自己
读到哪儿了，所以同一段对话不会读第二遍，也不会漏掉一段。你周二说过的话，周三还在。

同一件事不会被用两个名字记两遍。每一个写入者都要经过同一个判重器，它在新建页面之前会用
三种办法去找已有的页面——按路径，按同一个父节点下的名字或别名，以及按语义——因为一张图
真正会栽的地方不是遗忘，而是最后变成「Portal」「那个门户」`projects/portal` 和
`work/portal` 四个页面，每个都只知道四分之一。

## 它还会去哪里读

对话并不是你所知道的大部分东西待的地方。把代理指向它们真正待的地方，它就会保留一份可以
搜索、可以引用的副本：

| 种类 | 是什么 |
| --- | --- |
| `computer` | 你已接入的某台电脑上的一个代码检出或者一个文件夹 |
| `archive` | 放在某台电脑上的一份导出：按日期记的笔记，或者你写的脚本产出的 records |
| `skill` | 任何一个已安装的技能能列出来的东西：一个 wiki、一个问题追踪系统 |
| `web` | 你指定的一个网站，限定在你允许的前缀之内，深度由你设定 |
| `sent` | 你自己发出去的邮件 |

    teanode agent knowledge add "work" ~/work --computer laptop --under work
    teanode agent knowledge sync work
    teanode agent knowledge pause work      # 停止读取，已经找到的都留着
    teanode agent knowledge set work --cron "0 4 * * *" --under projects

`set` 就地改一个来源，你没提到的都原样不动。在它存在之前，想改一下读取的钟点，就只能把
这个来源删掉再加一遍，而那会忘掉它读过的每一份文档，并且让第一遍的代价付两次。仪表盘上
那一行的「编辑」，做的是同一件事。

一个 `computer` 来源是**在那台电脑上**读的。遍历、判别和拒绝，全都发生在你自己机器上跑
的那个守护进程里，只有通过了过滤的文本才会经过网络。在一个代码仓库里，清单就是 git 所
跟踪的东西，所以没人提交过的构建产物永远不会被读。一个文件是不是文本，看它能不能按文本
解码，而不是看它的扩展名。名字看起来像密钥或者环境变量文件的，会被拒绝；任何看起来像私钥、
令牌或者凭据的段落，也会被拒绝——在那台机器上就被拒绝、被计数、并写进这个来源的日志里，
所以服务器上的一个疏忽不会把这个口子放大。

随一条会话或者一封邮件一起来的图片也会被留下。夜里先看那些不花钱就能看到的东西——文件名、
大小、它来自哪条会话——然后决定哪些值得打开，因为描述一张图片是要花钱的，而大多数不过是头像。
打开的那些由模型读出来：屏幕上的报错、标识符、时间戳，这些就成了这个文件的文本，跟别的东西
一样可以搜索、可以引用。决定不打开的那些留着自己的字节，并用明白话带着理由，来源的页面会把
这三类都数出来。

从来源读到的一切都是数据，绝不是指令。它到达模型的方式，和一个抓取回来的网页是一样的。

哪些提交是**你的**，是按你标记为自己的那张联系人名片上的地址来判断的，所以请标一张：
`teanode contact me <id>`。一个来源如果发现了一些它认不出的提交地址，会把它们列出来并
指向通讯录，而不是悄悄地把你的工作一件都不算在你头上。

## 自己去搜

在这之前，能翻你自己那些文档的只有你的代理，也就是说得去问它，并且为那一轮付钱。现在你
可以直接问：

    teanode agent knowledge search "那次失败的迁移"
    teanode agent knowledge read <document-id> --from 4000

它就是代理的知识工具跑的那个搜索，翻的是同一批段落，排序方式也一样。标识符会在别的之前被
精确查一遍：把 `ResetPayloadAngularOffset` 粘进去，定义它的那个文件和行号会排在段落上面。
每一段都列在它所来自的文档下面，带着可以把那份文档读回来的标识符。`read` 接的就是那个标识
符，`--from` 说明从正文的哪里开始；一次没读到结尾的读取，会把接着往下读的那条命令打印出来。

知识页面上，这是「搜索它读过的东西」。「阅读」就地打开一份文档，「继续读」再往下接一段。

服务器配了嵌入模型的地方，排序同时按词和按语义来。没有的地方，答案会说明，而一句跟你的问题
一个词都不重合的同义改写是找不到的。

## 它为什么不知道那件事

一件明明白白写在页面上的事，仍然可能从来没出现在回答里；而从外面看，你没法判断是召回没
够着它、是某一夜把它退下去了，还是它的措辞让什么都对不上。那就问一问，一个问题会带进去
什么：

    teanode agent memory recall "那个门户什么时候上线？"

回来的是那一轮会拿到的那些页面，每个页面上的事实按页面自己的编号列着。它就是一轮真实对话
做的那个召回，所以这个答案就是真的那个。没有任何东西问过模型，也没有任何东西被标成用过，
所以你可以一边改页面一边想问多少遍就问多少遍，同一张图两遍的答案也一样。知识页面上，这是
「它会召回什么？」。

`teanode agent memory evaluate <file>` 把一整组问题送进同一条路，逐题说明它需要的那些事实
有没有被带上，并给出总计；只要有一题没中，退出码就不是零。在一夜之前和之后各跑一次，就能
看出这一夜改变了什么。

## 它在夜里做什么

当你安静了半小时、时间落在你设定的时段里、并且距离上一次至少六小时，你的代理就会把自己
的图整理一遍。它有属于自己的那一份当日预算——默认是三成——所以它不会吃掉你的一天；而且
它不删任何东西。

它读新到的东西，先新后旧、先你的后别人的：你写的，然后是你参与过的，最后才是其余的。一份
聊天存档只读你在场的那些会话；二十五万条别人的对话是好几年的阅读量，而且不关你的事，所以
它们保持可搜索，但不会被读。

它写这个月的记录。`time/2026/09` 和别的页面一样，是从一份完全不经过模型的摘要里搭起来
的——按仓库分的提交、你参与过的会话、你自己的笔记，噪声都去掉——然后再用你自己的说法写
出来。对当前这个月来说，这是一晚一次调用。

它重写有变动的页面，合并说的是同一件事的事实，并把长得太大的页面拆成按主题分的子页面。
它给连线重新称重：每条连线都被稍微调低，然后两头今天都被你用到的连线会升上去——所以今天
用过的连线，一夜之后比开始时更高。半年没人要过的事实会不再主动冒出来，但你搜的时候它们
还在。

然后它从要紧的地方出发，在图上走五步，问一问两个连得上、但并不直接相邻的页面之间，是不是
真有一层关系。「没有」是常见的答案，也是对的答案。当答案是「有」的时候，它会写下一条连线，
并附上支持这条连线的那句话，权重是你亲口说出来的那种的一半：剩下的一半要靠它有用来挣。
这是唯一一个会加上没人打过字的关系的环节，而这正是保留一张图、而不是一串列表的全部理由。

最后，它把你明天最可能问的那些问题写下来，拿每一个去问自己的记忆，并记下答不上来的那些。
没有人会去读答案；答不上来才是重点。凌晨三点发现的一个缺口，代价是一次模型调用；同一个
缺口在对话中间被发现，就是你眼睁睁看着自己的代理说它不知道。缺口只被记下来，从不被填上
——一次没有人在场的运行去给自己的问题编答案，正是一张图被虚构填满的方式。

    teanode agent dream log             # 最近几趟都做了什么
    teanode agent dream now             # 在下一个时钟点开始一趟
    teanode agent dream bootstrap on    # 尽可能快地把所有东西都读完

夜里的每一次调用，都是一次你可以打开来读的普通运行；代理页面顶上的那句话，会说昨晚一共
做了些什么。

## 它要花多少

第一次全量读取，等于一口气读完好几年的记录。把 `models.scan` 指向你自己的一个模型——
一个兼容 OpenAI 接口的服务，比如 Ollama、llama.cpp 或者 vLLM，按零价格声明成一个
provider——这样读取除了机器的时间之外不花钱。在按量计费的服务上，夜里的活动仍然被它那
一份当日预算、以及运维者设定的上限框住。

在数据库带 `pgvector` 扩展的地方，按语义的搜索就用它；没有的地方，一切照旧，在一个有界
的候选集上做。compose 文件里用的镜像是带这个扩展的。

## 什么都不会被删

每一次改动都会在页面上记下一条修订：改了什么、是谁改的——你、代理、那个归档对话的任务、
夜里的运行、正在被读取的来源——以及改之前是什么。没有「之前是什么」，一段历史就只能读，
不能撤销，而你去翻它的那一刻，想要的正是后面这一半。没有「是谁改的」，夜里写的页面和你
写的页面看起来一模一样。

夜里退下去的页面是被标成休眠，不是被删除：退出索引，但仍然搜得到。删除这件事归你做，而
删掉一个页面会连它下面的一起删掉。

每个页面和每条事实还带着最后写它的那个版本号，所以今天写下的一条规则，够得着上个月填起来
的图：夜里做的第一件事，就是把所有由更早版本写下的东西，拿现在的规则重新过一遍，划掉不合
规则的——记在页面的历史里，连同它原先说的那些话。

## 在你把它指向什么之前

除非模型是你自己跑的，否则它就是第三方，而你的代理送过去的东西，就是离开了你服务器的东西。
由此有三件事。

先加一个来源，把它写出来的东西读一遍，再加下一个。一个来源是关于一整条路径底下所有东西的
决定；而打开按语义的搜索，送出去的不只是之后新来的，还有已经在那里的。

如果材料敏感，就把代理指向你自己的 Ollama 或者 vLLM。同样的功能照常运转，归档的质量取决
于你跑的模型，而且没有任何东西离开这台机器。

在把这个开放给所有人之前，先读一读 `agent.features`。运维者就是在那里说明人们可以打开
什么的——一个想要分类、但不想要知识来源的运维者，应该在那里说清楚，而不是指望没人找到那
个开关。
