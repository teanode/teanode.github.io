まずはアシスタントだけで始めます。ドメインもメールのポートもいりません。自分のドメインのメールはあとから加えられ、すでにあるものはそのまま残ります。

## 必要なもの

- 動かしっぱなしのコンピューターと、compose プラグイン付きの Docker。compose ファイルが PostgreSQL を起動します。
- 考えるためのモデル。OpenAI、Anthropic、Gemini の API キー、すでに払っている ChatGPT のプラン、あるいは自分の Ollama か vLLM。
- iPhone のアプリや、そのコンピューターから離れたところで使うには、前に置く HTTPS のアドレス。リバースプロキシならなんでも。

## 1. サーバーを起動する

    mkdir -p /opt/teanode && cd /opt/teanode
    curl -LO https://raw.githubusercontent.com/ziyan/teanode/main/deploy/docker-compose.assistant.yml
    echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)" > .env
    chmod 600 .env
    docker compose -f docker-compose.assistant.yml up -d

待ち受けるのはそのコンピューター自身のループバックアドレスのポート 8080 だけで、ほかでは待ち受けません。

## 2. ダッシュボードを取得する

http://127.0.0.1:8080/ を開きます。TeaNode が目の前のコンピューターではなくサーバーで動いているなら、先に SSH のトンネルでつなぎます。

    ssh -L 8080:127.0.0.1:8080 you@your-server

最初の訪問者がただひとつのアカウント、つまり管理者を作るので、すぐにこの手順を済ませてください。

## 3. アシスタントをオンにする

**管理 → サーバー → セットアップ**を開きます。いちばん上のカードではすでに**パーソナルアシスタント**が選ばれているので、そのままにします。その下に残っている手順が順に並び、それぞれ済んだかどうかが表示されます。

1. **モデル提供元を接続してテスト。** **管理 → エージェント → モデル**で、**プロバイダーを追加**します。**名前**は自由（たとえば `openai`）で、**API キー**にキーを入れるか、自分の Ollama や vLLM のアドレスを入れ、ほかは空のままにします。**請求用キー**は別の用途です。保存してから**テスト**を押します。それから**既定**のモデルを選んで保存します。まずは提供元の小さく安価なモデル（OpenAI なら `gpt-5-mini`）で十分で、名前の一部を入力すると一覧が絞り込まれます。**埋め込み**モデル（OpenAI なら `text-embedding-3-small`）は任意で、選ぶと記憶を意味で検索できるようになります。
2. **アシスタントを有効にする。** **管理 → エージェント → 一般**で**有効**をオンにして保存します。どの保存でも再起動が必要と表示されますが、再起動は次のステップで一度だけで十分です。
3. **このインスタンスを再起動する。** 提供元、モデル、「有効」はサーバーの起動時に読み込まれます。このステップの**今すぐ再起動**を押します。**管理 → サーバー → 情報**からもできます。
4. **自分のエージェントをオンにする。** エージェントは各利用者が**設定 → あなたのエージェント**で自分でオンにします。セットアップのページにも自分の分をオンにするボタンがあります。

それからあいさつしてください。一覧の最後の**アシスタントを開く**か、どのページでも右下の丸いチャットボタンを押します。

## 4. 電話から使う

ポート 8080 を HTTPS のアドレスを持つリバースプロキシの後ろに置き、そのプロキシのアドレスをサーバーの設定の信頼するプロキシに加えて、そのアドレスでダッシュボードを開きます。iPhone のアプリがつなぐのもそのアドレスです。

## 自分のメールも

自分のドメインでメールを送受信するには、代わりにメールの compose ファイルで動かすか、あとで**管理 → サーバー → セットアップ**からこのサーバーにメールを加えます。

### メールに必要なもの

- ドメインと、その DNS レコードを編集できること。
- 固定のグローバルアドレスを持ち、インターネットからポート 25、80、443、587 に到達できる
  ホスト。メールプログラムで読みたいなら 993 も。
- compose プラグイン付きの Docker（上と同じ）。

### メールつきで起動する

    mkdir -p /opt/teanode && cd /opt/teanode
    curl -LO https://raw.githubusercontent.com/ziyan/teanode/main/deploy/docker-compose.yml
    docker run --rm ghcr.io/ziyan/teanode:latest config env --output - \
      --hostname mail.example.com --domain example.com > .env
    chmod 600 .env
    docker compose up -d

`mail.example.com` はサーバーの名前に、`example.com` はメールを受けたいドメインに置き換えて
ください。ホスト名は MX レコードが指す先になるので、DNS レコードを追加できる名前である必要が
あります。

起動する前に `.env` を開き、`TEANODE_TLS_ACME_EMAIL` に証明書機関から連絡が届くアドレスを
設定してください。ほかはすべて動く既定値です。このファイルにはデータベースのパスワードが
入っているので `chmod 600` にします。サーバーは最初の起動時に HTTP-01 で証明書を取得するので、
ポート 80 がインターネットから届く必要があります。

compose ファイルは ClamAV も起動します。任意なので、要らなければファイルから消してください。
これだけでメモリを 2GB ほど使います。迷惑メールの採点はサーバー内蔵のフィルターが行うので、
そのために別のプログラムは要りません。

### アカウントを作る

`https://mail.example.com/` を開きます。最初に訪れた人がただひとつのアカウントを作り、
そのアカウントは管理者で、自分のメールボックスを持ちます。ですからすぐに行ってください。
競争したくなければ、シェルから作ることもできます。

    docker compose exec teanode teanode user create you

### DNS レコードを公開する

ダッシュボードはドメインに必要な DNS レコードをすべて列挙し、定期的に確認して、まだ足りない
ものを示します。DNS プロバイダーでそれらを公開してください。MX レコードがメールを届かせ、
SPF、DKIM、DMARC のレコードがそれを信頼されるものにします。

### アドレスをメールボックスに向ける

メールボックスは、アドレスが向けられるまで何も受け取りません。ドメインの **エイリアス** タブで
種類に **メールボックスへ配送** を選び、自分のものを選んでひとつ追加します。パターン `^you$` で
`you@example.com` が自分のものになります。別のアカウントからメールを送り、受信箱に未読で
届くのを確かめてください。

別の場所へ行くべきアドレスは転送にします。`^hello$` のようなパターンは `hello@example.com` を
いま読んでいる受信箱、webhook、別のメールサーバーへ送り、空のパターンは他のどれにも一致しな
かったものを受け取るキャッチオールです。ひとつのドメインで両方できます。

### メールプログラムで読む

**メールボックス設定 → メールプログラム** でアプリパスワードを作り、デバイスの名前を付けて、
自分のアドレスと一緒に Apple Mail や Thunderbird、スマートフォンに入力します。プログラムは
ポート 993 の IMAP で読み、587 で送信します。ほとんどのプログラムはアドレスから自分で見つけ
ます。パスワードは一度しか表示されません。
