TeaNode サーバーのすべてのアカウントは、自分だけのエージェントを持てます。届いたメールを
読み、仕分け、下書きを書き、それについての問いに答えるものです。このページは、運用者が
何を有効にするのか、そして人がそれで何をするのかについてです。

モデルと誰かのメールのあいだには二つのスイッチがあり、どちらも手で入れなければなりません。
運用者がモデルサービスを設定して機能を有効にしますが、それだけでは誰にもエージェントは
できません。そのうえで各自が自分のものを有効にし、メールボックスをひとつずつ渡します。
その両方が起きるまで、メールについての何ひとつどこへも送られません。

## 何が要るか

モデルサービスひとつ。TeaNode は OpenAI、Anthropic、Gemini と、OpenAI API に答える
ものすべてと話します。そこには同じマシンの [Ollama](https://ollama.com/) も含まれ、
それが何ひとつサーバーから出ていかない構成です。

ほかには何も要りません。エージェントは他のすべてと同じ実行ファイルの中で動き、仕事を
取り出す待ち行列も同じ PostgreSQL の中にあります。

## 有効にする

運用者として、サーバーページの **エージェント** タブで、プロバイダーを追加します。種類、
どこで待ち受けているか、その鍵。そのうえで、どのモデルがどの仕事をするかを決めます。
`default` は必須、`fast` は安い仕事が使うもの、`embedding` は意味での検索を可能にする
ものです。テストはプロバイダーの行にあります。

    teanode settings set agent enabled=true
    teanode settings describe agent          # すべてのキーと、その型

鍵は保存される前にサーバーシークレットで封じられます。ドメインの署名鍵と同じです。
データベースのダンプには暗号文が入り、別のシークレットで起動したサーバーはそれを読めず、
読めないと告げます。

そして人として、**設定 → エージェント** で、自分のエージェントを有効にし、メールボックスを
ひとつ渡します。渡すのはメールボックスごとで、以下のすべてもそうです。ひとつのアドレスでは
仕分けを望み、別のアドレスでは何も望まない、ということがあるからです。

## 何をするか

**届いたものを仕分ける。** 分類、優先度、誰かが返事を待っているかどうか、一行の要約、
そしてそのメールが求めていること。行の上のしるしとして現れ、「スター付き」の隣に「優先」
ビューがあります。メールボックスのルールはその判断を読めます。「分類がニュースレターなら
Reading へ移す」。そしてそのルールは、配送のときではなく、仕分けが済んでから走ります。

**要約と下書き。** 三通を超えた会話にはその上に要約が畳まれ、会話が伸びるにつれて書き
直されます。返信するとき、作成欄が下書きを申し出ます。この返信に何をさせたいかを言うと、
その文章があなた自身の声と署名でエディターに落ちてきます。送るのはいつでもあなたです。

**許せば、代わりに答える。** メールボックスは、あなたが書いた方針のもとでエージェントに
代理で返信させられます。誰に答えてよいか、どんな種類のメールに、いつ、返信がどれだけ待つか、
一日に何通まで。どの返信も下書きで止まり、取り消すか引き取るかを選べる帯が付きます。手を
入れれば、それが引き取ったということです。書く前と送る前に、不在時の自動返信が登るのと同じ
階段を登ります。メーリングリスト、バウンス、自動メール、迷惑メール、あなた宛でないメールに
返すことは決してありません。

**あなたの問いに答える。** ダッシュボードのすべてのページにある引き出しと、端末の
`teanode agent ask`。ダッシュボードが使うのと同じ操作を通して、あなたとして、ちょうど
あなたの権限で働きます。メールを検索し、読み、振り分け、下書きし、フォルダーとルールを
面倒みます。取り消せないこと、そしてサーバーの外へ出ることは、あなたが承認するか断るかする
カードの前で止まります。

**憶えている。** あなたについての事実を、会話をまたいで。会計は誰か、どう署名するか、
何には絶対に自動で答えないか。あなたの手からも学びます。仕分けた先とは違う場所に自分で
入れたメールは、次の実行で見せられる例になります。

## いくらかかり、どう抑えるか

すべての実行は数えられ、運用者はトークンでも金額でも上限を置けます。`agent.limits` に
`dailyTokensPerAgent` と `monthlyTokensPerServer` があり、その隣に `dailyCostPerAgent`
と `monthlyCostPerServer` があります。ひとりだけに与えることもできます。

    teanode agent admin limit alice --cost 5

金額の予算は、各プロバイダーに設定された価格で、モデルごとに計算されます。小さいモデルと
大きいモデルを走らせている配備でも、それぞれ正しく課金されます。両方の予算が置かれている
ときは、先に尽きたほうがその日を終わらせます。`agent.currency` は、金額がどの三文字コードで
書かれるかを言います。表示と書式のためのもので、換算はしません。

人は自分のその日を、チャット窓の頭にあるリングとして見ます。運用者はサーバーページの
エージェントタブで、日、種類、メールボックス、モデルごとの使用量を見ます。

## 有効にする前に量っておくこと

自分で走らせているのでない限り、言語モデルは第三者です。そこへ届くメールは、あなたの
サーバーから出ていったメールです。そして自分のメールサーバーを運用する理由はたいてい、
まさに出ていかないことです。そこから三つ。

まずひとつのメールボックスを渡し、それが何をするか見てから次を渡してください。渡すことは
メールボックス丸ごとについての決定であり、意味での検索を有効にすると、これから届くものだけ
でなく、すでにそこにあるものもベクトルにするために送られます。

メールが機微なものなら Ollama に向けてください。同じ機能が動き、仕分けの質は走らせる
モデル次第で、そして何ひとつこのマシンから出ません。

全員に開く前に `agent.features` を読んでください。人が何を有効にできるのかを決めるのは
そこです。仕分けは欲しいが自動返信は要らない運用者は、みながスイッチに触れないことを当てに
するのではなく、そこでそう言うべきです。
