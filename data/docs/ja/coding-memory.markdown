Claude Code と Codex のセッションは、どれも、動いているチェックアウトについてファイルのほかは
何も知らずに始まります。あなたのエージェントは多くを知っているかもしれません。そのプロジェクトが
何か、何がなぜ決まったか、前に何がうまくいかなかったか、昨日どこで手を止めたか。セッションは
MCP でそれを尋ねることもできますが、自分に欠けていると知らないことのためにツールを呼ぼうと
モデルが決めることは、めったにありません。だから TeaNode は、知っていることをセッションの目の前に
置きます。どちらのツールもセッションの節目ごとに走らせるフックを通してです。

## 設定のしかた

コーディングをするコンピューターごとに、次のようにします。

1. `teanode auth login` でサインインします。フックがツールの環境にあるトークンではなく、
   保存したプロファイルを使うようにするためです。
2. `teanode hook install claude-code` か `teanode hook install codex`、あるいは両方を
   走らせます。フックは `~/.claude/settings.json` か `~/.codex/hooks.json` に、すでにある
   すべてのフックの隣に加えられます。
3. Codex では、`~/.codex/config.toml` の `[features]` に `hooks = true` を書いてフックを
   有効にします。Codex は、新しいフックが初めて走る前に、それを信頼するかをあなたに尋ねます。

セッションに見せられるものはエージェントの記憶から来るので、その質は、記憶がそのチェックアウトに
ついて何を読んだか次第です。チェックアウトを置いているフォルダーに
[ナレッジのソース](/doc/memory#ほかにどこを読むか)を向け、そのコンピューターの
Claude Code か Codex のソースも加えてください。そうすれば過去のセッションも読まれます。

`teanode hook uninstall claude-code`（または `codex`）は TeaNode のフックを外し、ファイルの
ほかの部分はそのまま残します。

## セッションに見せられるもの

### 始まるとき

セッションが始まるとき、再開するとき、あるいは圧縮されるとき、そのチェックアウトのプロジェクトの
ページが見せられます。要約と、そこに載る事実のうち最もよく使われるもの、そしてチェックアウトが
載っているほかのプロジェクトのページについても同じものです。セッションがファイルから自分で
読めること（リモート、言語、チェックアウトの場所）は省かれます。

そのディレクトリで、あるいはチェックアウトのどこかで開かれた最後のセッションも見せられます。
どのツールか、そのタイトル、最後に動いていたのはいつか、あなたの最後の三つの頼みごと、そして
最後の答えの出だし。これはモデルが書くものではありません。保存された履歴から読んだ、話された
とおりのものなので、履歴が読まれればすぐにそこにあります。再開したセッションに、それ自身が
見せられることはありません。

架空のチェックアウトでは、セッションの始まりはこう見えます。

    <teanode-memory>
    TeaNode, the person's agent, remembers this about the checkout at
    ~/src/greenfinch-site (page projects/greenfinch-site). Facts are cited
    as page#number; its memory tool reads a page whole.

    projects/greenfinch-site: The marketing site for Greenfinch, built
    with Astro and deployed from main.
    - projects/greenfinch-site#4 The pricing page must render without
      JavaScript, because the partner portal embeds it.
    - projects/greenfinch-site#9 Images go through the CDN's resizer,
      never into the repository.

    The last session in this directory (claude-code, "Pricing table on
    phones", last active 2 hours ago):
    The person's last requests:
    - make the pricing table scroll sideways on a phone
    - keep the first column pinned
    Its last answer: The table now scrolls inside its card and the plan
    names stay in view…
    </teanode-memory>

### プロンプトのたびに

あなたが打つプロンプトはどれも、エージェントの turn と同じ想起を受けます。違いはひとつだけで、
運んでよいものがチェックアウトのプロジェクトに限られることです。つまり、プロジェクトのページ、
その下のページ、誰かが口にしたリンクでつながったプロジェクト、もの、フォルダー、そしてそれが
リンクする話題です。人、月、あるいはそれにたまたま触れているだけの広い話題は決して含みません。
だからビルドについての問いが、あなたのメールやお金や同僚を第三者のモデルに持ち込むことはなく、
外されたページが予算を使うこともありません。

ページの隣には、プロンプトに近い教訓が来ます。教訓とは、エージェント自身の仕事が教えたこと
（いつ当てはまるか、何がうまくいったか、何を避けるか）で、それが名指すコマンドが成功したときに
だけ残されます。だからエージェントが自分の仕事について言っただけのことでは、決して足りません。
意味の上でプロンプトに十分近い教訓だけが見せられます。

想起は、足すものがないときは黙っています。

- セッションの直近の五つのプロンプトで見せたページは、もう一度見せません。
- 三語に満たないプロンプト、スラッシュコマンド、ツールが自分から送るテキスト（終わった
  バックグラウンドのタスクなど）は、何も想起しません。
- プロジェクトから何も想起しないプロンプトには、何も見せません。

代わりに記憶のすべてから想起させるには、`--everywhere` を付けてインストールします。

### 答えのあとで

答えが終わったとき、セッションが圧縮されたとき、あるいはセッションが終わったとき、そのコンピューター
の Claude Code か Codex のソースに、次の予定の時刻を待たずに今すぐ履歴を読み直すよう頼みます。
そのソースは、そのコンピューターを待っているほかのソースより先に回るので、セッションはおよそ一分
以内に検索できるようになり、そのディレクトリの次のセッションは、これがどこで止まったかを知って
います。そうしたソースがコンピューターになくても、次のセッションには、それまでに記憶に入った
ものが見えます。

## どのチェックアウトか

チェックアウトのプロフィールには、それがどこに、どのコンピューターにあるかが記録されています。
フックは、自分が走っているコンピューターの上で、セッションのディレクトリを含むいちばん深い
チェックアウトを探します。

このコンピューターのソースが一度も読んだことのないチェックアウトは、代わりに git のリモートで
照らし合わせます。別のコンピューターの同じパスは、何の証しにもならないからです。そのとき
セッションには、記憶がそのプロジェクトをどこで、どのコミットで読んだかが伝えられ、読んだのと
同じコンピューターでも別のコミットなら、その記憶が古いかもしれないことも伝えられます。記憶が
知っているどのチェックアウトにも入っていないディレクトリには、何も見せません。

## セッションが何を見せられるかを見る

三つの場所が、セッションを始めることなく、何かを使ったと記録することもなく、セッションが
見せられるものをそのまま見せます。

- `teanode agent memory checkout [directory]` はセッションの始まりを表示します。
  `--prompt "<words>"` を付けると、そのプロンプトが何を想起するかを表示し、`--everywhere` は
  それを広げます。
- ナレッジのページの「想起」ダイアログにあるチェックアウトの欄が、同じことをします。
- エージェントの `memory` ツールに `checkout` の操作があるので、エージェントに尋ねられます。

## 何も見せないとき

フックがツールの邪魔をすることは決してありません。サーバーに届かないフックや、ほかの理由で
失敗したフックは、何も見せずにきれいに終わり、何がうまくいかなかったかは、キャッシュの
ディレクトリの下の `hook.log` に書かれます（Linux では `~/.cache/teanode/hooks`）。何かが
見せられるはずのセッションに何も見せられなかったなら、次を確かめてください。

- チェックアウトが読まれていること。そのディレクトリで `teanode agent memory checkout` を
  走らせると、どのページを見つけたかが分かります。
- そのコンピューターで、フックが名指すプロファイルでサインインしていること。
- Codex なら、フックが有効になっていて、そのフックが信頼されていること。

## いくらかかるか

プロンプトひとつにかかるのは、埋め込みがひとつと、いくつかのクエリーです。セッションの始まりは、
それより少し多くかかります。モデルに何かを書かせることはなく、何も使ったと記録しないので、
コーディングで忙しい一日が、エージェントが何を大事だと思うかを動かすことはありません。
