TeaNode は自分で持つ、エージェントつきのメールボックスです。自分のドメインの本物の
アドレスと、あなたのサーバーから出ていかない、各自のための助手。

メールの側は小さなメールサーバーです。すべてのドメイン宛のメールを SMTP で受け取り、
本物かどうかを確かめ（SPF、DKIM、DMARC、ARC）、任意でウイルスと迷惑メールを検査し、
そのうえでここのメールボックスに振り分けるか、そのまま渡します。いま読んでいる受信箱へ、
webhook へ、あるいは別のメールサーバーへ。それらのアドレスから返信や送信もでき、ドメインの
鍵で署名されるので、迷惑メール扱いにならず相手に届きます。

メールボックスはダッシュボードでも、IMAP で好きなメールプログラムでも読めます。メールボックスを
持たせたくないアドレスは転送すればよく、ひとつのドメインで両方できます。

助手はもう一方の側で、誰かが有効にするまで動きません。メールボックスを渡せば、届いたものを
仕分け、あなたの声で下書きを書き、ちょうどあなたの権限であなたのメールについての問いに
答えます。もっと渡せば、連絡先、あなた自身のコンピューター、あなた自身のブラウザーのタブ、
そしてウェブに届きます。同じマシンの Ollama か vLLM に向ければ、そのどれについても何ひとつ
あなたのハードウェアから出ません。[エージェント](/doc/agents)がその全部を語ります。

## なぜ

ドメインのメールを運用するには、たいていプロバイダーに預けるか、Postfix、Dovecot、
OpenDKIM、OpenDMARC、SpamAssassin とポリシーデーモンを組み合わせて、それらの足並みを
揃え続けるかのどちらかです。これは実行ファイルひとつと PostgreSQL データベースひとつで、
メールを信頼できるかどうかを決める認証は、後付けではなく組み込みです。

## どんな見た目か

ダッシュボードはバイナリにコンパイルされていて、他に配備するものはありません。開くと自分の
メールボックスが出てきて、サーバーを運用するページは **管理** の向こうにあり、権限が許す
ものだけが見えます。

管理する側では、このサーバーが扱ったすべてのメール、それぞれについて下した判断、そして

スクリプトを取り除いたメール本体が出てきます。

## 必要なもの

- ドメインと、その DNS を編集できること
- 固定アドレスを持ち、ポート 25、80、443、587 に到達できるホスト。メールプログラムに
  メールボックスを読ませるなら 993 も
- PostgreSQL。設定と、メールボックスと、扱ったメールのために

他には何もいりません。AWS のアカウントも不要です。証明書は HTTP-01 で自動取得されるので、
設定する DNS API もありません。S3 互換のオブジェクトストレージは任意で、複数のインスタンスを
動かすときにだけ意味があります。保存されたメールを共有させるのがそれです。

## できること

**メールボックス。** アカウントごとにひとつ。フォルダーは何段でも入れ子にでき、名前を変え、
移動し、上に留められます。検索はひとつのフォルダーでも、メールボックス全体でもでき、送信者、
宛先、件名、日付、添付での絞り込みが付きます。ルールは届いたメールを振り分け、すでに振り分けた
メールに対して後から流すこともできます。添付を一度だけアップロードする下書き、署名、書いた
相手から貯まる連絡先、そして機械やメーリングリスト、同じく不在中の相手には返さない不在時の
自動返信があります。メールはいくつのフォルダーが持っていてもひとつだけ保存され、ひとつでも
持っている限り残ります。

**IMAP。** ポート 993 と、143 の STARTTLS。メールプログラムが同じメールボックスを読みます。
デバイスごとにアプリパスワードがあり、IMAP のサインインにも、ポート 587 のサブミッションから
メールボックスのどのアドレスとして送るときにも使います。

**運用者が用意するなら、あなただけのエージェント。** サーバーをモデルサービスに向ければ
――OpenAI、Anthropic、Gemini、あるいは同じマシンの Ollama――各自が自分のエージェントを
有効にできます。届いたものを仕分け、あなたの声で下書きを書き、ちょうどあなたの権限で
メールについての問いに答え、あなたが書いた方針のもとでは代わりに返事もします。誰かが有効に
するまで動かず、メールボックスを渡されるまで何も見えません。配送の途中でモデルに届くものは
ありません。[エージェント](/doc/agents)が、何が要るか、まず何を量るべきかを述べています。

**サブスクリプション。** メールボックスが受け取るすべてのメーリングリストが専用のページに
並び、それぞれから抜ける道は送信者自身が書いたヘッダーから読み取られます。抜けることは
ブラウザではなくこのサーバーが依頼するので、どのアドレスがどのメールをいつ開いたかを送信者
に伝えません。ミュートはもうひとつの答えで、しばしばこちらのほうが良いものです。リストは
届き続け、アーカイブに振り分けられ、すでに読んだ扱いになります。途中で退読の手段を取り除か
れたニュースレターも、リストとしてまとめられ、送信者が出口を出し惜しんだように見せるのでは
なく、なぜ出口を示せないのかをページが説明します。

**印。** 送信元のドメインが自分のメールのために公開しているロゴを、そのリストの隣に表示
します。表示するのは DMARC を通ったメールについてだけです。印は「誰が送ったか」についての
主張であり、証明されていないメールに付いた印は、その人になりすましている者を助けます。
自分のドメインの印もここから公開できます。ファイルをアップロードすれば、DNS のタブが何を
公開すべきかと、何がそれを効かなくするか――多くは DMARC のポリシーが none であること――を
言います。

**すべてを認証する。** 受信時に SPF、DKIM、DMARC、ARC を検査し、結果をメールごとに表示
します。送信メールには DKIM 署名を付け、転送するメールには ARC チェーンを残すので、転送先でも
検証を通ります。

**柔軟に転送する。** エイリアスは正規表現でアドレスを照合し、メールボックスへ配送するか、
メールアドレス、HTTP エンドポイント、別のメールサーバーへ送ります。空のパターンは
キャッチオールで、他のどれにも一致しなかったものを受け取ります。

**送信メールを中継する。** サブミッションポートにデバイスごとの SMTP 資格情報を用意し、
それぞれを送信元アドレスひとつに制限することもできます。

**人、グループ、ロール。** 権限が各自に見えるものを決めます。Administrator、Operator、
Member が最初から入っていて、すべて編集できます。グループをドメインに結び付ければ、その権限は
そこまでしか届きません。OpenID Connect プロバイダーによるシングルサインオンは、自分の
ディレクトリのグループに従います。ユーザー、グループ、ロール、ドメイン、エイリアス、資格情報、
メールボックスへの変更はすべて監査ログに残ります。

**メールを見せる。** ダッシュボードはメールをメールとして描画します。認証の判定、配送の試行と
失敗の理由、そしてスクリプトを取り除いた本文。リモート画像は求めるまで読み込みません。

**書いたメールを送る。** 変数と翻訳を持つテンプレート、それを包むレイアウト、自分のドメインから
配信する画像、そして受信者のメールソフトがそれを取得したかどうかの記録。

**ドメインについて報告する。** 受け取った DMARC 集計レポートは解析して保存されます。誰かが
自分のドメインを偽っていることに気づけるのは、これのおかげです。

**第二のプログラムなしで迷惑メールを採点する。** サーバー内蔵のフィルターが、すでに分かって
いること——SPF、DKIM、DMARC、ARC の結果、送信ホストに前方確認済みの逆引き名があるか、
HELO で名乗った名前——を読み、公開ブロックリストを DNS で引き、ダッシュボードで印を付けた
メールで訓練した分類器を当てます。外部の SpamAssassin デーモンも、望む配備のために引き続き
サポートされます。

**任意の追加機能、すべて既定でオフ。** ClamAV、GeoIP、保存メールの S3 ミラー、アドレスの
評判が悪いホスト向けの送信 SOCKS5 プロキシ、ワイルドカード証明書が必要なときの DNS-01。

## メールはどう通り抜けるか

1. SMTP のリスナーがプロトコルを話し、必要なら STARTTLS と認証を行い、エンベロープを作ります。
2. エンベロープは四つの道のどれかを選びます。署名されたバウンスやレポートのアドレスなら配送
   状態通知か DMARC 集計レポート、資格情報があれば送信のサブミッション、それ以外は受信メールです。
3. 受信メールは検査され——SPF、DKIM、DMARC、ARC を並行で、そのあと任意のウイルスと迷惑メールの
   検査——それぞれの検査が何を判断したかとともに記録されます。宛先のローカル部はそのドメインの
   エイリアスと照合され、一致するごとに配送がひとつ作られます。メールボックス、別のアドレス、
   webhook、あるいは別のメールサーバーへ。
4. メールボックスへの配送は、保存されたメールへの参照を置き、メールボックスのルールを適用し、
   未読の数を更新します。外への配送はドメインの鍵で署名されて中継され、失敗すれば決まった間隔で
   再試行され、キューのページが相手のサーバー自身の言葉で理由を伝えます。

どの段階も、ダッシュボードが何が起きたかを見せられる場所です。記録しているのはそのためです。

## 設定

設定はデータベースにあるので、複数のインスタンスがひとつの答えを共有し、ダッシュボードでの
変更はすべてに届きます。ドメイン、エイリアス、資格情報、アカウントは一件ずつ管理される行です。
環境変数はそのデータベースの場所だけを言い、残りはすべて保存されています。

    teanode domain create example.com
    teanode alias create example.com --pattern '^you$' --kind mailbox --mailbox <メールボックス id>
    teanode alias create example.com --pattern '^hello$' --kind email --email you@example.net

[コマンドライン](/doc/command-line)は API 全体に届き、[設定](/doc/configuration)は
すべての項目を記録しています。
