悪用できる問題については、公開の issue を立てないでください。メールの処理（SPF、DKIM、DMARC、ARC の検証、ヘッダーの解析、MIME リーダー）、認証、セッションの扱い、証明書の発行、そしてダッシュボードのフィルターの背後にある集計パイプラインが含まれます。

このリポジトリの [Security タブ](https://github.com/ziyan/teanode/security/advisories/new) から、GitHub のプライベートな脆弱性報告で知らせてください。アドバイザリーが公開されるまでメンテナーにしか見えず、公開の issue ではない話し合いの場になります。

何をしたか、何が起きたか、何を期待していたかを教えてください。再現するメッセージ、つまり `.eml` ファイル、SMTP のやり取りの記録、リクエストは、説明よりも価値があります。

## 対象になるもの

このリポジトリのプログラムを、既定の設定で動かしたもの。具体的には、ポート 25 でのメールの受け付け、587 での認証付きサブミッション、`/api/v1` 配下のすべて、そして取得する証明書です。

## 対象にならないもの

- 運用者自身の資格情報や設定へのアクセスを必要とするもの。これはシングルテナントのソフトウェアで、運用者は信頼されています。運用者が自分のネットワークに届くための文書化された手段、つまり webhook エイリアス、転送先、リレーホストは機能です。
- 接続先として設定されるサービス。PostgreSQL、ClamAV、SpamAssassin、オブジェクトストア。設定されたとおりに信頼されます。ドキュメントがそれらを公開インターネットから離しておくよう求めるのはそのためです。
- 量によるサービス拒否。アルゴリズム的なサービス拒否は対象です。
