会話と会話のあいだにあなたを忘れてしまうエージェントは、行儀のよい検索窓にすぎません。
このページは、あなたのエージェントが何を保つのか、それがどうやって、あなたが頼まないうちに
書かれるのか、ほかにどこを読みに行くのか、そして誰も話しかけていないあいだに、それらへ何を
するのかについてです。

どれも、あなたがエージェントを有効にし、何かを渡してから先の話です。ここに書かれていること
の背後には、あなたが自分で入れたスイッチがあります。

## かたち

エージェントが知っていることは、覚え書きの一覧ではなく、**ページ**でできた図です。

**ページ**とは、あなたの暮らしが名前を持っているもののことです。人、プロジェクト、組織、
場所、もの、話題、ひと続きの時間。それはパスに住みます――`people/alice-chen`、
`projects/greenfinch`、`time/2026/09`――そしてそのパスが、どこでもそれの住所です。プロンプトの
中でも、引用の中でも、コマンドラインでも、ダッシュボードの URL そのものでも。

**事実**は、ページに載る一文で、番号が付いています。`people/alice-chen#3` は、
エージェントが Alice について知っている三つめのことで、答えの中でそう引用され、あなたが
その行をもう一度見つけるのもその番号でです。番号は使い回されないので、#3 を消しても、その
番号が次に書かれるものへ渡ることはありません。どの事実も、どの言葉から来たか、そしてその
言葉がどこから来たか――会話、メール、ファイル――を連れているので、一行は確かめられます。
どの行が確かめられてどの行が確かめられないかは、ダッシュボードが言います。

事実は日付を二つ持ちます。答える問いが違うからです。それが本当だったのはいつか、そして
エージェントがそれを知ったのはいつか。「大阪に引っ越した」のは 2019 年で、知ったのは先週の
火曜です。2019 年についての問いが欲しいのは前者です。

**リンク**は二つのページを結び、どう結ばれているかを言います。「関連」ではなく、
`works_on`、`member_of`、`knows`、`owns`、`uses`、`located_in`、`decided_in`、
`about`、`part_of`。どれも両方向に読めます――Alice からあるプロジェクトへのリンクは、彼女のページでは
「手がけている」、プロジェクトのページでは「手がけられている」と読めます――そして長く誰も
触れていないリンクは過去形で言われます。もう本当ではないかもしれない、と示すのに、これが
いちばん小さく正直なやり方です。

これらはすべて **設定 → ナレッジ** で読み、直せます。そしてそこにあることは、コマンド
ラインにもすべてあります。

    teanode agent memory index                      # 図のいちばん上
    teanode agent memory get people/alice-chen
    teanode agent memory note projects/greenfinch "支払い条件が九十日になった"
    teanode agent memory link people/alice-chen projects/greenfinch --relation works_on
    teanode agent memory move notes/kittiwake things
    teanode agent memory history projects/greenfinch

## 頼まれなくても書く

これの最初の版は、turn の途中でモデルに記憶を書かせるものでした。実際のサーバーで 456 の
turn のあいだに書かれたのは二つ、どちらもテストでした。仕事と記憶の道具を渡されたモデルは、
仕事をします。

だから書くことは turn の中にはありません。会話が静かになったあとで仕事がひとつ走り、何が
話されたかを読み、その会話が教えたことを書き留めます。見つけた、あるいは作ったページ、原文
とともに足された事実、引かれたリンク。どこまで読んだかを憶えているので、同じやり取りを二度
読むことも、ひとつ飛ばすこともありません。火曜に言ったことは、水曜にもあります。

同じことが二つの名前で二度書かれることはありません。書き手はみな同じ判定器を通り、ページを
作る前に三つのやり方で既存のページを探します――パスで、同じ親の下の名前か別名で、そして
意味で。図が本当に失敗するのは忘れることではなく、「Portal」「あの窓口」`projects/portal`
`work/portal` という四つのページになって、それぞれが四分の一ずつ知っている状態になること
だからです。

## ほかにどこを読むか

あなたが知っていることの大半は、会話の中にはありません。それが実際にある場所へエージェント
を向ければ、検索でき、引用できる写しを保ちます。

| 種類 | 何か |
| --- | --- |
| `computer` | 接続したコンピューターのチェックアウト、あるいはフォルダー |
| `archive` | チャットの書き出し、あるいは日付のついたノートのフォルダー |
| `skill` | 入れてあるスキルが一覧できるもの。wiki、課題管理 |
| `web` | あなたが挙げたサイト。許した接頭辞の内側を、決めた深さまで |
| `sent` | あなた自身の送信済みメール |

    teanode agent knowledge add "work" ~/work --computer laptop --under work
    teanode agent knowledge sync work
    teanode agent knowledge pause work      # 読むのをやめ、見つけたものは残す

`computer` の情報源は、**そのコンピューターの上で**読まれます。歩くことも、見分けること
も、断ることも、あなた自身のマシンで動かしている常駐プログラムの中で起き、フィルターを通っ
たテキストだけが線を渡ります。リポジトリの中では、目録は git が追いかけているものなので、
誰もコミットしていないビルド結果が読まれることはありません。ファイルがテキストかどうかは、
テキストとして解けるかで決まり、拡張子では決まりません。名前が鍵や環境ファイルに見えるもの
は断られ、秘密鍵、トークン、資格情報に見える一節も断られます――そのマシンの上で断られ、数え
られ、その情報源の記録に名前が残ります。だからサーバー側の手違いが、この口を広げることは
ありません。

情報源から読まれたものはすべてデータであって、指示ではありません。取ってきたウェブページと
同じ扱いでモデルに届きます。

どのコミットが**あなたのもの**かは、あなた自身だと印を付けた連絡先カードの住所で決まります
ので、ひとつ印を付けてください。`teanode contact me <id>`。置き場所のわからない住所の
コミットを見つけた情報源は、それらを並べて住所録を指します。あなたの仕事をひとつも
あなたのものにしないまま黙っている、ということはしません。

## 夜のあいだに何をするか

あなたが三十分静かで、あなたが決めた時間帯の中にあり、前回から六時間以上経っているとき、
エージェントは自分の図に取りかかります。その日の予算のうち自分の取り分――既定で三割――を
持っているので、あなたの一日を食べることはありません。そして何ひとつ消しません。

届いたものを、新しいものから、あなたのものから読みます。あなたが書いたもの、次にあなたが
加わったもの、最後にそれ以外。チャットのアーカイブは、あなたがそのスレッドにいたところだけ
読みます。ほかの人たちの二十五万のスレッドは何年分もの読書で、しかもあなたの用ではないので、
検索できるまま、読まれずに置かれます。

その月を書き上げます。`time/2026/09` はほかと同じただのページで、モデルをまったく使わずに
組み立てた要約から作られます――リポジトリごとのコミット、あなたが加わったスレッド、あなた
自身のノート、雑音は落として――それを、あなた自身の言い方で書き上げます。いま開いている月に
ついては、一晩に一度の呼び出しです。

変わったページを書き直し、同じことを言っている事実をまとめ、大きくなりすぎたページを主題
ごとの子ページに分けます。リンクの重みを付け直します。どのリンクも少しずつ下げられ、それ
から両端ともあなたが今日使ったリンクが上がります。だから今日使われたリンクは、一夜のあとで
始まりより上にいます。半年のあいだ誰も必要としなかった事実は、招かれずに出てくることを
やめます――探せば、まだそこにあります。

そのあと、大事なところから図を五歩歩き、つながってはいるが隣り合ってはいない二つのページの
あいだに、本当の関係があるかを問います。「ない」がふつうの答えで、正しい答えです。「ある」の
ときは、それを裏づける一文を添えてリンクが書かれます。重みは、あなたが口にしたリンクの半分
です。残りの半分は、役に立つことで自分で稼ぎます。誰も打ち込まなかった関係が加わるのはここ
だけで、一覧ではなく図を保つ理由は、まるごとこれです。

最後に、明日あなたが訊きそうな問いを書き出し、ひとつずつ自分の記憶に当ててみて、答えられな
かったものを記録します。答えは誰も読みません。答えられなかったことのほうが目的です。夜中の
三時に見つかった穴の代金はモデルの呼び出しひとつで、同じ穴が会話の途中で見つかるというのは、
自分のエージェントが「わかりません」と言うのをあなたが見ることです。穴は書き留められるだけ
で、埋められることはありません――誰もいないところで走る実行が自分の問いに答えをこしらえる、
それが図が作り話で埋まっていく道筋だからです。

    teanode agent dream log             # 直前の夜が何をしたか
    teanode agent dream now             # 次の時計の刻みで一度始める
    teanode agent dream bootstrap on    # できるかぎり速く、全部読む

夜が行う呼び出しはどれも、開いて読めるふつうの実行です。エージェントのページのいちばん上の
一文が、昨夜が何になったかを言います。

## いくらかかるか

最初の取り込みは、何年分もの記録を一度にです。`models.scan` をあなた自身のモデルに向けて
ください――Ollama、llama.cpp、vLLM のような OpenAI 互換のサーバーを、価格ゼロの
プロバイダーとして宣言する――そうすれば、読むのにかかるのはマシンの時間だけです。従量課金の
サービスでも、夜はその日の予算の取り分と、運用者が置いた上限に収まったままです。

意味での検索は、データベースに `pgvector` 拡張があればそれを使い、なければ、これまでどおり
上限のある候補の集合の上で動きます。compose ファイルが使うイメージには、それが入っています。

## 何ひとつ消えない

どの変更もページに一件の改訂を残します。何が変わったか、誰が変えたか――あなた、エージェント、
会話を書き留める仕事、夜の実行、読まれている途中の情報源――そして、その前が何だったか。
「その前」がなければ、履歴は読めても戻せません。そして見に行った瞬間に欲しいのは、その後ろ
半分です。誰が変えたかがなければ、夜が書いたページとあなたが書いたページは見分けがつきません。

夜が下げたページは、消されたのではなく休眠と印が付きます。索引からは外れ、検索では見つかり
ます。消すのはあなたの仕事で、ページを消せばその下も消えます。

どのページも事実も、最後に書いたビルドを連れています。だから今日書かれた規則が、先月埋め
られた図に届きます。夜が最初にするのは、古いビルドが書いたものすべてを今の規則にかけ直し、
通らないものを消すことです――ページの履歴に、それが前に言っていた言葉とともに残して。

## 何かを指す前に

モデルを自分で動かしているのでない限り、それは第三者であり、エージェントがそこへ送るものは、
あなたのサーバーから出ていったものです。そこから三つ。

情報源をひとつ足し、それが書いたものを読んでから、次を足してください。情報源とは、あるパス
の下のすべてについての決定です。そして意味での検索を有効にすると、これから届くものだけで
なく、すでにそこにあるものも送られます。

中身が機微なものなら、自分の Ollama か vLLM にエージェントを向けてください。同じ機能が
動き、書き留めの質は動かすモデル次第で、何ひとつこのマシンから出ません。

全員に開く前に `agent.features` を読んでください。人が何を有効にできるかを運用者が言うのは
そこです。仕分けは欲しいが知識の情報源は要らない運用者は、みながスイッチを見つけないことを
当てにするのではなく、そこでそう言うべきです。
