Claude Code と Codex のセッションをいくつも、それぞれ自分の端末で開いているなら、エージェントは
あなたの隣でそこで働けます。接続したすべてのコンピューターのすべてのセッションを見て、それぞれが
したことを読み、あなたに見える形でひとつに指示を入力し、セッションが止まって尋ねる質問を
あなたに届けます。だから机を離れていても、引き出しから、電話から、あるいは MCP を話すチャット
アプリから答えられます。

これは [herdr](https://herdr.dev) を通して行います。コーディングエージェントのための端末の
ワークスペースマネージャーで、端末をペインに収め、それぞれのコーディングエージェントを見分けます。

## 何が要るか

- コンピューターで herdr が動いていて、そのペインにコーディングのセッションがあること。
- そのコンピューターで、最新の `teanode` から `teanode computer start` が走っていること。
  コンピューター上のプログラムが herdr のソケットを見張り、サーバーに報告します。ほかに入れる
  ものはありません。

セッションは各自のものです。プログラムはあなたとしてサインインし、あなたのペインを見るのは
あなたのエージェントだけです。

## 何をするか

**一覧にする。** エージェントのページの「接続」タブにある「herdr のセッション」カード、
`teanode computer herdr list`、そしてエージェントの `herdr` ツールは、どれもすべてのセッションを
見せます。herdr で見つけるとおりの名前、作業中か、待機中か、質問中か、どのコーディング
エージェントか、コンピューター、ディレクトリ、タイトル。質問しているセッションが先に来ます。

**読む。** セッションの履歴の最後の turn、あるいはそのペインが今見せているもの。

**入力する。** 指示はあなたの目の前でペインに入力されます。あなたが入力したのと同じで、作業中の
セッションはそれを turn の中のメッセージとして読みます。プロセスも、履歴も、画面もひとつで、
あなたとエージェントが共有し、あなたはいつでも引き取れます。

**質問を届ける。** セッションが止まって何かを尋ねるとき（どの選択肢を取るか、コマンドを走らせて
よいか、編集してよいか、計画を承認するか）、その質問はあなたの主な会話に書き込まれます。引き出しが
選択肢をボタンにして開き、同じ質問がつないだチャットアプリにも届きます。先に答えたほうが勝ちます。
コンピューター上のプログラムは答えを押す前に画面をもう一度読み、質問が消えたか変わったものへの
答えは断ります。

**終わったら知らせる。** エージェントにセッションを見守るよう頼むと、そのセッションが turn を
終えたとき、頼んだ会話が起こされます。だから「テストが通ったら教えて、それからプルリクエストを
開かせて」が通じます。

**開き、閉じる。** あるディレクトリで新しい Claude Code か Codex のセッションを、その名前を
付けたワークスペースの新しいタブに開きます。頼めば権限の確認を切って開きます。セッションを
閉じるのは、作業中でないときだけです。

## どこからでも

これらの操作はどれもエージェントの `herdr` ツールにあるので、エージェントに届くものは何でも
あなたのコーディングのセッションに届きます。引き出しでの[電話](/doc/voice)は、各セッションが
何をしているかを尋ね、待っているものに答えられます。ChatGPT、Grok、あるいは Model Context
Protocol を話すほかのアシスタントも、[あなたのサーバーにつなげば](/doc/mcp)同じです。電話から、
車の中なら声でも、セッションがどうなっているかを尋ね、ひとつに次に何をするかを伝えてください。

MCP クライアントに対して、このツールはあなたの言葉どおり読み取り専用だと告げるので、こうした
アシスタントは毎回尋ねずにそれを走らせます。たいていのアシスタントは、書き込むツールを常に許す
ことを認めないからです。送ることと答えることは、ダッシュボードでも確認のカードを出しません。
答えのたびにカードが出るのは、人が望む以上だったからです。カードが欲しければ、自分の「先に確認」
の一覧に `herdr` を入れてください。

## セッションの中でも、エージェントが知っていること

コーディングのセッションには、それが動いているチェックアウトについてエージェントが知っていることも
見せられます。herdr があってもなくても使えます。そのコンピューターであなたのサーバーにサインインして、
`teanode hook install claude-code`（または `codex`）を走らせます。フックはツール自身のものの隣に入り、
`teanode hook uninstall` は TeaNode のものだけを外します。

- **セッションが始まるとき**、プロジェクトのページとそこで最もよく使われる事実、そしてそのディレクトリ
  の前のセッションがどこで止まったか（その題名、あなたの最後のいくつかの頼みごと、最後の答えの出だし）
  が見せられます。
- **プロンプトを打つと**、そのプロンプトが想起するものが渡されます。そのプロジェクト、その下のページ、
  それにつながる仕事に限るので、ビルドについての問いがメールやお金のことをコーディングツールに持ち
  込むことはありません。直近の五つのプロンプトで見せたページは繰り返さず、短いプロンプトやスラッシュ
  コマンドは何も想起しません。
- **答えが終わると**、そのコンピューターにあるそのツールのソース（加えてあれば）にすぐ読み直すよう
  頼むので、セッションは一分以内に検索でき、次のセッションはこれがどこで止まったかを知っています。

このコンピューターが一度も読んだことのないチェックアウトは git のリモートで照らし合わせ、記憶がその
プロジェクトをどこで、どのコミットで読んだかをセッションに伝えます。サーバーに届かないフックは何も
見せず、ツールを止めることもありません。Codex がフックを走らせるのは、`~/.codex/config.toml` の
`[features]` に `hooks = true` があるときだけです。`teanode agent memory checkout` は、あるディレクトリの
セッションが何を見せられるかを表示し、ナレッジのページの「想起」ダイアログのチェックアウトの欄も同じ
ことをします。

## 質問していると、どう分かるか

画面からです。プログラムは、今の Claude Code と Codex が質問、承認、計画のために描く形を見分け、
各セッションの状態を herdr のものを受け取らずに自分で決めます。形の上に指示を入力すれば、それに
答えてしまうからです。形を違うふうに描くコーディングエージェントは、見分け方を覚えるまで見分け
られません。そのセッションは待機中か不明と表示され、画面はそれでも読めます。

`teanode computer herdr setup` は、そのコンピューターの Claude Code の設定に報告用のフックを、
すでにあるものの隣に、先にファイルの写しを取ってから入れることもできます。フックは起きたことを
報告するだけで、何も決めません。Claude Code の設定を変えるので、頼まれたときにだけ入れます。

コンピューター上のプログラムが再起動しても（アップグレードのたびに起きます）、まだ待っている
質問も、見守りも失われません。
