Model Context Protocol は、プログラムどうしが「私にはこれができます、名前で呼んでください」
と伝え合うための取り決めです。TeaNode はその両端に立っています。二つの向きが共有しているの
は線の上の形式だけで、ほかはほとんど何も共通していません。

**外向き**には、エージェントがあなたの持つサーバーへつなぎ、そこの道具がエージェントの道具に
なります。**内向き**には、TeaNode 自身がこの取り決めに応えます。あなたが動かすコーディングの
道具やエディターが、エージェントの道具を使え、言葉でエージェントに問いを投げられます。

## 応える側：あなたの道具を、あなたのエディターから

    POST /api/v1/mcp

どの要求もトークンを自分で運び、要求と要求のあいだに何も残らないので、どちらの側が再起動
しても失うものはありません。プログラムにトークンを渡す方法は三つあります。

    # 住所を指し、ブラウザーで承認する
    claude mcp add --transport http teanode https://mail.example.com/api/v1/mcp

    # コマンドラインがすでにサインインしているマシンで
    claude mcp add teanode -- teanode agent mcp serve

    # あるいは自分で API トークンを渡す
    claude mcp add --transport http teanode \
        https://mail.example.com/api/v1/mcp \
        --header "Authorization: Bearer tnt_..."

一つめはどこにも何も写しません。トークンなしで断られたプログラムは、どこで登録し、あなたを
どこへ送ればよいかを教えられます。あなたはダッシュボードにサインインし（まだなら）、どの
プログラムが頼んでいるかを見て、許可します。プログラムは秘密を持たずに登録します。誰かの
マシンに置かれたプログラムには秘密を守れないからです。そしてトークンを受け取るときに、頼んだ
のが自分であることを証明します。

受け取るトークンは API トークンより狭く、エージェントの道具にだけ効き、GraphQL API やほかの
すべてには断られます。更新のたびに取り替えられるので、こうしたトークンは API トークンと並べ
ず、プログラムごとに一覧されます。設定の「アプリ」でプログラムの名前を変えたり切り離したり
でき、切り離せばそれが持つトークンはすべて取り消されます。`teanode app` でも同じです。

自分で登録せず、クライアント識別子を求めてくるホスト型のアシスタントもあります。そのアシスタ
ント自身のコールバックの住所に対して一つ登録してください。その住所ちょうどでなければなりま
せん。承認は、プログラムが登録した住所にしか送られないからです。

二つめは二つめの実装ではなく、一本の管です。`teanode agent mcp serve` は、すでにサインイン
している profile で同じ端点へメッセージを送るので、サーバーが差し出すものをそのまま差し出し
ます。

三つめはどちらもできないプログラムのためのものです。API トークンはそのアカウントの権限を
まるごと持つので、配るかどうかは運用者の判断で、しまっておくのはあなたの役目です。

プログラムがエージェントの道具を通してしたことは、エージェントの「活動」タブに、呼んだ道具と
投げた問いのひとつずつが、種類 `mcp` として並びます。

### 呼ぶ側に何が差し出されるか

あなたの一覧まるごとを、会話と同じやり方でふるいにかけたもの。あなたの権限が許すものから、
運用者が切ったものを引き、つないだサーバーの道具と、運用者が入れたスキルを足したもの。メール
を読めない人にメール検索は差し出されません。そもそもその人の一覧に無いからです。どの道具にも
注記、読み取り専用か破壊的かが付いているので、プログラムもエージェントと同じように、のぞくこと
と変えることを見分けられます。

どれも、トークンがもともと許していなかったものを何ひとつ与えません。ブラウザーで承認した
プログラムはエージェントの道具に留められ、API トークンを渡されたプログラムは、この端点の隣に
ある GraphQL API を通して、そのアカウントの権限が許す操作をもともとすべて行えます。変わるのは
要求の形であって、何を頼めるかではありません。

`tools/call` は道具を走らせます。モデルが走らせるかどうかを決める会話が始まるわけでは
ありません。呼ぶ側はもう何が欲しいか分かっていて、あいだにモデルを置けば、お金がかかり、
秒がかかり、そのうえ毎回違う答えになります。どの呼び出しも、あなたとして実行され、あなたと
して記録されます。

呼び出しは確認済みとして届きます。あなたの道具は走らせる前にあなたに尋ねますし、このサーバー
から届くカードはありません。あなたがその道具に渡した資格情報が、あなたがそう決めたという
しるしです。道具が信頼できないと印を付けたものは、返す前に包まれます。エージェント自身の
ループが包むのと同じやり方です。向こう側はそれを自分のモデルへ渡すので、こちらのモデルと
同じだけ、注意を告げる必要があります。

### 動かすのではなく、訊く

`teanode_ask` は言葉の問いを取り、エージェントの答えを返します。その後ろには、道具ひと揃い
と、あなたについての記憶がまるごと控えています。ふつうなら六回の呼び出しを組み立てるところ
が、一度で済みます。

区切りは、一回の turn にかかる時間ではなく、呼ぶ側が待ってくれる時間で決まります。多くは
一回の呼び出しに一分ほどしか待ちません。55 秒経つと、そこまでに語られたものを返し、その
会話の名前を告げます。turn はそのまま続き、その会話を指して問いなしでもう一度呼べば、残りを
受け取れます。そのあいだに終わった turn も返され、語ったことを再生するので、遅れて戻っても
答えは聞けます。実行が終わって十分経てば、答えのある場所は会話そのものです。

確認のカードを上げて止まった turn には、この道具からは答えられません。答えはそのことを言い、
カードはダッシュボードで待っていると告げます。ただ止まった答えのように見せることはしません。

### 外してある道具が二つ

`ask_user` は、見ている人の前に問いを置くためのものです。呼び出しの向こう端には人がいます
が、その人が見ているのは自分の道具の画面で、このサーバーはそこに描けません。これに手を伸ばす
道具は、推測した答えではなく、そう言うエラーを受け取ります。

`tool_search` は、長い一覧を必要になるまでモデルの要求から遠ざけておくためのものです。
この種の道具は一覧を一度引いて持っておくので、一覧そのものを渡すほうが役に立ちます。

## つなぎに行く側：エージェントが使うサーバー

もう一方の向きです。運用者がサーバーを宣言します。名前、住所、そして人がそこでどう認証する
か。認証なし、共有の資格情報、各自のもの、あるいは OAuth。そのうえであなたが自分の資格情報
をつなぐか、OAuth を使うサーバーならブラウザーで承認します。資格情報は保存される前に
サーバーシークレットで封じられます。

    teanode agent mcp list
    teanode agent mcp connect tracker --credential -
    teanode agent mcp disconnect tracker

返ってきたものはサーバーの名前で名前空間を付けられ、あなたの一覧に合流します。各サーバーの
道具の一覧は五分保たれ、三度続けて失敗するとそのサーバーの道具は次の間隔まで引き下げられ
ます。ひとつのサービスが落ちても、エージェントの道具ひと揃いを道連れにしないためです。

どの道具も、サーバーが付けた注記、たとえば読み取り専用や破壊的といった印を連れてきます。
読み取り専用の道具は尋ねずに走り、運用者が読み取り専用と挙げたものも同じです。破壊的なものは
尋ねます。それ以外の呼び出しは速いモデルが判断し、あなたに代わって他の人へ働きかけるとき、
お金を動かすとき、注文を出すか取り消すとき、何かを消すときにだけ尋ねます。口座をのぞくたびに
カードを出すと、人は読まずに承認するようになり、それはカードが無いより悪いからです。そうした
サーバーが返すものはすべてデータです。指示することはありません。

承認をループバックの住所にしか返さないサービスもあります。自分のマシンの上のプログラムのため
の方式です。そう宣言されたサーバーは、代わりにあなたの接続したコンピューターを通して承認され
ます。そのコンピューターのブラウザーで済ませれば、ダッシュボードが接続を仕上げます。

## 自分自身へ向けると

運用者がこのサーバー自身の端点を、エージェントのつないだサーバーのひとつとして宣言すること
を、何も妨げてはいません。そうするとエージェントは自分の一覧の名前空間付きの写しを持ち、
呼び出しはそのまま外へ出て戻ってきます。握手は TeaNode を名乗るクライアントを断りますし、
こちらのクライアントはまさにそう名乗ります。そして `teanode_ask` はエージェント自身の一覧
には決して入らないので、最初の関門を抜けた輪でも、そこを通って再帰することはできません。
